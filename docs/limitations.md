# Known limits and trust boundary

- **Version-specific integration:** Jellyfin 12.4.0 only. The native provider is located through a public API by its exact implementation type name. Other versions need a new integration test, even if the package loader accepts them.
- **Hardlink-compatible storage is mandatory:** no cross-volume links, symlink or copy fallback. Linux identity uses `statx` (device major/minor and inode), Windows uses volume serial and file index. Linux needs a libc/kernel providing `statx`. Network and union filesystems can expose different behavior; no blanket SMB/NFS/mergerfs compatibility claim is made.
- **No hostile concurrent directory mutation guarantee:** paths and ancestors are checked for confinement, symlinks and reparse points before discovery and immediately before mutations. These are path-based operations, not a descriptor-relative transactional filesystem API. An adversarial concurrent directory/junction swap between validation and a native operation remains a TOCTOU risk. Use administrator-controlled library trees. Do not deploy this version against trees where untrusted users can replace directories during scans. Static symlink/junction/traversal tests do pass. Ordinary concurrent creation of a destination is refused without overwrite.
- **Owned replacement is not a filesystem transaction:** the recorded identity is checked again before unlinking an old owned destination; the new link is created without overwrite. Cancellation, a crash or failure can leave a temporary gap, retried by a later scan. Hostile concurrent replacement of that directory entry is subject to the trust boundary above. Sources are never deliberately unlinked.
- **Generic write completion cannot be proved:** age, nonzero length, a readable handle, identity and before/after stat checks detect common partial files. Windows file sharing blocks cooperative concurrent writers while inspecting. Unix and some network filesystems cannot universally rule out a paused writer with old timestamps. Very recent/changing files are deferred; use atomic rename on download completion where available. The plugin does not alter download clients or wait for long periods inside scans.
- **Conservative matching:** editions, release-group/quality suffixes and ambiguous titles are not guessed away. Absolute episode numbers are not converted to season/episode numbering. Unknown naming layouts need explicit rules or mappings. The source and target episode keys must have equal season/type/edition information.
- **Existing sidecars and ownership:** found hardlinks can be used as existing files, but are never adopted. A lost registry prevents future automatic replacement/cleanup of those links. Corrupt registries fail closed. Persistent state assumes one Jellyfin process/plugin instance owns it.
- **Native probing remains native:** embedded MKA tags can override filename title/language. Flags from a filename are ignored for multi-stream containers by Jellyfin. Sync, cuts, timing, codecs, transcoding and client playback remain Jellyfin/media concerns. Initial/full refreshes can do an extra native probe within the same refresh.
- **No live playback claim:** the automated integration test checks persisted `MediaStreams`, flag/language metadata and native file identities. It does not click a real playback client or test a user's home storage/server.
- **UI:** administrator API/preview/report are exercised by real-server tests. Visual interaction with the installed Jellyfin web settings page has not been tested in a browser.

Test results apply to the platforms and storage described in [the verification record](verification.md).
